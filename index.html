01 · Search

Natural-language property search

An independent FastAPI microservice that reads free-text queries in either language, extracts type, budget, location and lifestyle wishes, and returns structured criteria the Laravel backend can filter on.

LLM intent extraction · Pydantic schemas · prompt engineering
02 · Scoring

Neighborhood Vibe Score

Each property gets a 0 to 10 score for safety, quietness and amenities by combining nearby OpenStreetMap places, found with Haversine distance, with sentiment analysis of reviews around them. A batch pipeline turns the same method into a city-wide Vibe Heatmap, with a sentiment cache that removes duplicate LLM calls.

Geospatial analysis · sentiment analysis · batch pipelines

How the score sees a street

Everything within 500 m counts

The service draws a circle around the listing, gathers every mapped place inside it, and weighs what people say about those places. Parks and cafés push quietness and amenities up; bars and busy roads pull quietness down.

Production debugging

When search returned zero homes

After launch, searches came back empty or with the wrong homes. The AI was parsing correctly, so I traced the request across every layer. It turned out to be five separate bugs.

  • dead route

    The frontend called an API route that no longer existed. Rewired it to the live search endpoint.

  • timeout

    A 20-second frontend timeout cut off the slower search call. Combined with free-tier cold starts on Render, results never arrived.

  • mislabeling

    Property type was guessed from title words, so “Apartment in Casablanca Boutique Villas” showed as a villa. Switched to the real type_id.

  • flat score

    The match percentage became nearly constant once filtering moved to the server. Rewrote the scoring so price and fit still separate results.

  • pagination

    A limit bug in the FastAPI pagination dropped results. Fixed it and checked each patch with test scripts before shipping.
